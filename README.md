# Лабораторная работа №1. Загрузка, анализ и предобработка табличных данных

## 1. Описание датасета

**Название:** HCV data (Hepatitis C Virus)  
**Источник:** [UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/571/hcv+data)  
**Краткое описание:** Набор данных содержит лабораторные показатели доноров крови и пациентов с гепатитом С, а также демографические значения, такие как возраст.  
**Обозначение пропусков:** строка `"NA"`.

### Описание признаков (14 столбцов):
Все признаки, кроме `Category` и `Sex`, являются числовыми (лабораторные данные, атрибуты 5–14).
1. `X` – ID пациента / номер записи.
2. `Category` – диагноз (категориальный): `'0=Blood Donor'`, `'0s=suspect Blood Donor'`, `'1=Hepatitis'`, `'2=Fibrosis'`, `'3=Cirrhosis'`.
3. `Age` – возраст в годах.
4. `Sex` – пол (`f`, `m`).
5. `ALB` – альбумин.
6. `ALP` – щелочная фосфатаза.
7. `ALT` – аланинаминотрансфераза.
8. `AST` – аспартатаминотрансфераза.
9. `BIL` – билирубин.
10. `CHE` – холинэстераза.
11. `CHOL` – холестерин.
12. `CREA` – креатинин.
13. `GGT` – гамма-глутамилтрансфераза.
14. `PROT` – общий белок.

---

## 2. Правило определения типа признака

Признак считается **категориальным**, если хотя бы одно его непустое значение (не равное маркеру пропуска `"NA"`) не может быть успешно распарсено как число с плавающей точкой (`double`) с помощью `std::from_chars`. В противном случае признак считается **числовым**.

**Обоснование:** Данный датасет представляет собой результаты анализов крови. Подавляющее большинство признаков отражают концентрацию тех или иных веществ, что по своей природе является непрерывной числовой величиной. Категориальными являются только диагноз (`Category`) и пол (`Sex`), которые содержат буквы и не могут быть интерпретированы как числа.

## 3. Стратегии предобработки

### 3.1. Заполнение пропусков (Импутация)
- **Числовые признаки:** заполняются **медианой** (`NumericImputation::Median`), вычисленной на этапе анализа исходных данных.
- **Категориальные признаки:** заполняются специальной дополнительной категорией `"__MISSING__"`. Исходный набор категорий при этом сохраняется.

### 3.2. Масштабирование числовых признаков
По умолчанию используется **Robust scaling** (устойчивое к выбросам масштабирование).  
Формула: 
$$ x' = \frac{x - Q_{0.5}}{Q_{0.75} - Q_{0.25}} $$
где $Q_{0.5}$ – медиана, $Q_{0.25}$ и $Q_{0.75}$ – первый и третий квартили.

**Обоснование выбора:** В медицинских данных (результаты анализов крови) часто встречаются экстремальные выбросы, связанные с тяжелыми состояниями пациентов. Robust scaling использует квантили, которые гораздо менее чувствительны к выбросам, чем среднее значение и стандартное отклонение (как в Standard scaling) или минимальные/максимальные значения (как в Min-Max).

**Обработка вырожденного случая:** Если знаменатель равен нулю ($Q_{0.75} = Q_{0.25}$), это означает, что интерквартильный размах равен нулю (большая часть значений одинакова). В этом случае функция возвращает `0.0`. Это математически обосновано: при нулевом размахе отклонение значений от медианы также стремится к нулю, и неопределённость вида $0/0$ разрешается в пользу центра распределения, что безопасно для последующих вычислений в моделях машинного обучения.

### 3.3. Кодирование категориальных признаков
Выбран способ **One-Hot Encoding** (унитарное кодирование).

**Обоснование выбора:** При Ordinal-кодировании категориям присваиваются числа $0, 1, 2, \dots$. Для признака `Category` это создало бы **ложный порядок** (например, модель могла бы интерпретировать `'3=Cirrhosis'` как математически "больше" или "важнее", чем `'0=Blood Donor'`, что лишено смысла). One-Hot encoding создает независимые бинарные столбцы для каждой категории, полностью устраняя эту проблему.

**Детерминированность порядка:** Перед кодированием уникальные категории сортируются **лексикографически** (по алфавиту). Это гарантирует, что при повторных запусках программы на одних и тех же данных категории всегда будут получать одни и те же индексы и имена столбцов (например, `Category_0=Blood Donor`, `Category_1=Hepatitis` и т.д.).

**Влияние на модели:** 
- *Ordinal-кодирование* вносит ложный порядок, что критично и вредно для линейных моделей, но может быть несущественно или даже полезно для деревьев решений.
- *One-Hot Encoding* является универсальным и безопасным выбором для любых типов моделей.

## 4. Бинарный формат сохранения

Итоговая матрица сохраняется в бинарный файл (`.bin`), содержащий: количество строк, количество столбцов, порядок хранения (`Layout`) и непрерывный массив значений типа `double` (IEEE 754).

Рядом с бинарным файлом сохраняется текстовый файл `feature_names.txt` со списком имён столбцов (по одному на строку) — это позволяет в последующих работах сопоставить номер столбца матрицы с исходным признаком.

**Почему этот формат пригоден только для учебной задачи:**
1. **Зависимость от архитектуры:** На 32-битных и 64-битных системах типы данных (например, `std::size_t`) занимают разное количество байт. Файл, созданный на одной системе, может быть неверно прочитан на другой.
2. **Разный порядок байт (Endianness):** Разные процессоры (Intel и некоторые ARM) хранят байты внутри числа в разном порядке. Код не делает специальных преобразований, поэтому файл не является кроссплатформенным.
3. **Отсутствие версии формата:** Нет заголовка с версией формата, что делает невозможным обратную совместимость при изменении структуры файла.
4. **Нет защиты от повреждений:** В файле не хранятся контрольные суммы (хеши). Если файл повредится, программа не выдаст предупреждение, а прочитает случайные данные.

## 5. Сборка и запуск

Для сборки проекта требуется компилятор с поддержкой C++20 (GCC 12+ или Clang 16+) и CMake 3.20+. Рекомендуется использовать WSL (Windows Subsystem for Linux) или нативный Linux.

```bash
# 1. Создание директории сборки и конфигурация (Debug с санитайзерами)
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 2. Сборка проекта
cmake --build build

# 3. Запуск тестов 
ctest --test-dir build --output-on-failure

# 4. Запуск приложения
./build/app

### Параметры командной строки

| Флаг | Значение по умолчанию | Описание |
|------|------------------------|----------|
| `--input` | `data/data.csv` | Входной CSV-файл |
| `--output` | `data/transformed.bin` | Куда сохранить бинарную матрицу |
| `--bins` | `10` | Число интервалов гистограммы (должно быть > 0) |
| `--impute` | `median` | Стратегия импутации: `mean`, `median`, `zero` |
| `--scaling` | `robust` | Масштабирование: `minmax`, `standard`, `robust` |
| `--encoding` | `onehot` | Кодирование: `onehot`, `ordinal` |
| `--help` | — | Вывести справку |

Некорректные значения (например, `--bins 0`, `--scaling foo`) приводят к
понятному сообщению об ошибке и коду возврата `1`.

**Запуск с параметрами командной строки**

# Указать свой датасет
./build/app --input data/hepatitis.csv

# Выбрать стратегии
./build/app --scaling minmax --encoding ordinal --impute mean

# Изменить число интервалов гистограммы
./build/app --bins 20

# Указать путь для сохранения
./build/app --output results/matrix.bin

# Посмотреть справку
./build/app --help
