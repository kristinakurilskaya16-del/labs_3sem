# AGENTS.md

Этот файл описывает правила работы ИИ-агента в лабораторной работе по ООП на C++20.

## Структура проекта

```
lab1/
├── CMakeLists.txt          # Конфигурация сборки CMake
├── README.md               # Описание проекта, датасета, команд сборки
├── AGENTS.md               # Этот файл — правила для агента
├── docs/
│   └── agent_log/
│       └── lab_1.md        # Журнал работы с агентом
├── include/                # Заголовочные файлы
│   ├── types.hpp           # Column, FeatureInfo, DatasetInfo, TransformedDataset
│   ├── enums.hpp           # NumericImputation, Scaling, Encoding, Layout
│   ├── matrix.hpp          # Объявление класса Matrix
│   └── dataset.hpp         # Dataset, load_dataset, вспомогательные функции
├── src/                    # Исходный код
│   ├── dataset.cpp         # Загрузка, анализ, импутация, transform, вывод
│   ├── matrix.cpp          # Matrix: operator(), save, load
│   └── main.cpp            # CLI: парсинг аргументов, интерактивный цикл
├── tests/
│   └── tests.cpp           # Тесты (assert + CTest)
├── third_party/
│   └── cxxopts.hpp         # Header-only парсер аргументов командной строки
└── data/                   # Датасеты (не коммитятся в Git)
    ├── data.csv            # Исходный CSV
    ├── transformed.bin     # Бинарная матрица после предобработки
    └── feature_names.txt   # Имена столбцов итоговой матрицы
```

### Архитектура

- **`core`** (статическая библиотека: `dataset.cpp`, `matrix.cpp`) — вся логика:
  загрузка, анализ, импутация, масштабирование, кодирование, сериализация.
- **`app`** (`main.cpp`) — консольное приложение: парсинг аргументов, диалог с
  пользователем, вызовы `core`.
- **`tests`** (`tests.cpp`) — отдельная программа с `assert`-проверками,
  зарегистрирована в CTest.

### Ключевые типы

- `Column = std::variant<NumericColumn, CategoricalColumn>` — разнотипные столбцы.
- `std::optional<T>` — пропуски (не `-9999`, не пустая строка).
- `enum class NumericImputation / Scaling / Encoding / Layout` — стратегии.
- `DatasetInfo = std::unordered_map<std::string, FeatureInfo>` — статистика,
  отдельно от данных.
- `Matrix` — плотная матрица `double` с `Layout::{RowMajor, ColumnMajor}`.

## Технические требования

- **Стандарт:** C++20
- **Компилятор:** GCC 12+ или Clang 16+
- **Сборка:** CMake 3.24+
- **Цели сборки:**
  - `lab1_core` — статическая библиотека ядра (`src/dataset.cpp`, `src/matrix.cpp`)
  - `lab1_app` — консольное приложение (`src/main.cpp`)
  - `lab1_tests` — тесты (`tests/tests.cpp`), зарегистрированы в CTest
- **Предупреждения:** `-Wall -Wextra` без предупреждений
- **Санитайзеры:** AddressSanitizer + UndefinedBehaviorSanitizer в Debug-сборке
- **Стиль кода:** современный C++ с использованием `std::optional`, `std::variant`, `std::span`, `enum class`, `std::filesystem`

## Что МОЖНО поручать агенту

### 1. Разбор ошибок компилятора и санитайзеров
Агент может объяснять сообщения об ошибках, предупреждения компилятора, отчёты санитайзеров и предлагать исправления.

### 2. Помощь с CMake
Агент может генерировать и объяснять `CMakeLists.txt`, помогать с настройкой целей, санитайзеров, регистрации тестов.

### 3. Генерация README
Агент может писать README по проекту: описание датасета, команды сборки, пример вывода, описание бинарного формата.

### 4. Форматирование вывода в консоль
Агент может помогать с `std::format`, выравниванием столбцов, красивым выводом таблиц и гистограмм.

### 5. Объяснение возможностей стандартной библиотеки
Агент может объяснять, как работают `std::optional`, `std::variant`, `std::span`, `std::from_chars`, `std::filesystem`, алгоритмы ranges и другие средства C++20.

### 6. Автоматизация получения метаданных из таблицы
Агент может помочь извлечь названия столбцов, определить вид признаков, способ записи категориальных значений из CSV-файла (но не реализовывать это в коде — см. раздел "Что НЕЛЬЗЯ").

## Что НЕЛЬЗЯ поручать агенту

Согласно условию лабораторной работы, следующие части должны быть написаны **строго самостоятельно**:

### 1. Определение типа признака
Логика, которая решает, является ли столбец числовым или категориальным (например, попытка распарсить все значения как `double`).

### 2. Расчёт статистик и квантилей
Функции вычисления min, max, mean, variance, median, q05, q25, q75, q95.

### 3. Заполнение пропусков (импутация)
Метод `Dataset::impute()`, который заменяет `std::nullopt` на медиану/среднее/ноль или категорию `__MISSING__`.

### 4. Масштабирование числовых признаков
Функции `scale_value()` для MinMax, Standard, Robust scaling.

### 5. Кодирование категориальных признаков
Функция `encode_categorial()` для One-Hot и Ordinal encoding.

### 6. Бинарная сериализация
Методы `Matrix::save()` и `Matrix::load()`, работа с бинарными файлами, `reinterpret_cast`.

### 7. Проектирование представления датасета
Архитектура классов `Dataset`, `Matrix`, `TransformedDataset`, структур `NumericColumn`, `CategoricalColumn`, `NumericFeatureInfo`, `CategoricalFeatureInfo`.

## Стиль кода и соглашения

### Использование современных средств C++20
- **Пропуски:** `std::optional<double>` или `std::optional<std::string>` вместо `-9999` или пустых строк.
- **Разнотипные столбцы:** `std::variant<NumericColumn, CategoricalColumn>` вместо наследования.
- **Стратегии:** `enum class` (не строки, не магические числа).
- **Невладеющие представления:** `std::span<const double>` для вычислительных функций.
- **Файловые пути:** `std::filesystem::path` вместо `std::string`.

### Именование
- Классы: `PascalCase` (например, `Dataset`, `Matrix`).
- Функции и методы: `snake_case` (например, `load_dataset`, `get_num_rows`).
- Переменные: `snake_case` (например, `num_rows`, `clean_values`).
- Enum'ы: `PascalCase` для имени, `PascalCase` для значений (например, `Scaling::MinMax`).

### Обработка ошибок
- Ошибки ввода-вывода и парсинга — сообщение пользователю, не аварийное завершение.
- Исключения (`std::runtime_error`) для критических ошибок (не удалось открыть файл, несогласованный CSV).
- Некорректный ввод в интерактивном цикле — сообщение и продолжение цикла, не выход из программы.

### Тесты
- Тесты — отдельная программа `tests/tests.cpp`.
- Используют `assert()` из `<cassert>`.
- Возвращают 0 при успехе, ненулевой код при провале.
- Регистрируются в CTest через `add_test()`.
- В CMake для тестов добавляется `target_compile_definitions(lab1_tests PRIVATE NDEBUG=0)`, чтобы `assert()` работал даже в Release.

## Журнал работы с агентом

Все важные промпты и сгенерированный агентом код фиксируются в файле `docs/agent_log/lab_1.md`.

Для каждого эпизода указывается:
1. **Текст запроса** агенту.
2. **Что было получено** (код, объяснение, исправление).
3. **Что принято, что изменено, что отклонено** и почему.
4. **Как проверен результат** (команды сборки, запуск тестов, проверка вывода).

## Команды для проверки

### Сборка проекта

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

### Запуск тестов

```bash
ctest --test-dir build --output-on-failure
```

### Запуск приложения

```bash
./build/app --help
./build/app --input data/data.csv --bins 20
```

### Проверка на предупреждения

```bash
cmake --build build 2>&1 | grep -i warning
```

Вывод должен быть пустым.

### Проверка санитайзеров

Если в коде есть ошибка памяти или неопределённое поведение, ASan/UBSan выведут
подробный отчёт при запуске тестов или приложения в Debug-сборке.
