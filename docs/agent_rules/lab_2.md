# Лабораторная №2 — только задание со звёздочкой

**Статус:** активная работа.

Источник: «Лабораторная работа 2. Задание со звёздочкой», прежде всего разделы 1–2, 11–16.

## Какое задание выполняется

Только **решающий пень с эффективным поиском порога** (`DecisionStump`) для регрессии и классификации. Преподаватель прямо разрешил сдать только звёздочку, **без kNN**. Документ звёздочки самодостаточен; не использовать требования обязательной части kNN как дополнительные обязательства.

Решающий пень — основа для будущих дерева CART (работа №3) и случайного леса (работа №4). Требуется интерфейс `IModel`, эффективный поиск порога `O(d * n log n)` при дополнительной памяти `O(n)`, тесты и документация. Это контекст, **не разрешение агенту писать алгоритм**.

## Разрешённая помощь ИИ

**Ожидается:**
- выбор и настройка стиля документирующих комментариев (например, Doxygen);
- документирование **уже реализованного студентом** публичного интерфейса ядра: классов, методов, параметров, предусловий;
- настройка генерации документации и её сборка;
- проверка корректности сгенерированных комментариев совместно со студентом.

**Допускается с записью в `docs/agent_log/lab_2.md`:**
- форматирование консольных таблиц;
- чтение и обработка параметров запуска;
- вспомогательный код тестов;
- объяснение ошибок компилятора и санитайзеров.

Также допускается использовать ИИ как справочник для разъяснения языка C++ и библиотек, **без генерации запрещённой реализации**.

## Запрещённая помощь ИИ

Не поручать агенту **генерацию, дописывание, исправление или проектирование**:
1. Реализации решающего пня: выбора признака и порога, сортировки индексов, обновления агрегатов, критериев регрессии и классификации, предсказаний и обработки алгоритмических граничных случаев.
2. Индексации матрицы: `operator[]`, `at()` и связанной логики доступа.
3. Иерархии классов моделей, включая проектирование интерфейса и отношений наследования.
4. Иерархии исключений.

Нельзя обходить ограничения, называя работу «рефакторингом», «оптимизацией», «исправлением теста» или «вспомогательной функцией». Если тест или санитайзер выявляет ошибку в запрещённой части, агент сообщает диагностические данные, но студент исправляет код сам.

**Граница вспомогательных тестов:** агент может помогать с тестовой инфраструктурой и разрешённым вспомогательным кодом, но не генерирует реализацию пня или наивный алгоритм сравнения под видом тестового помощника. Если конкретный тест фактически требует написания запрещённого алгоритма, студент пишет его самостоятельно.

## Дополнительные требования задания (для проверки, не для генерации)

- Разделить отклик и признаки; при необходимости самостоятельно согласовать рефакторинг кода работы №1.
- Реализовать доступ к строкам матрицы через `std::span`, проверяемый `at()`.
- Поддержать регрессию и классификацию, детерминированное разрешение ничьих, константные признаки и отсутствие допустимого разбиения.
- Предусмотреть исключения для перечисленных в условии ошибочных ситуаций; ядро не печатает сообщения об ошибках.
- Написать тест сравнения с наивной реализацией, тесты граничных случаев и исключений; запускать их через CTest с ASan/UBSan в Debug.
- Вести Git-историю по ходу работы (коммиты выполняет студент или агент только с отдельного разрешения).
- Подготовить README с оценкой сложности и собранную документацию.

## Порядок работы агента

1. Прочитать этот файл и конкретный запрос студента.
2. Определить, относится ли действие к разрешённым; при сомнениях уточнить, **не писать код**.
3. Перед изменениями сообщить план и получить согласие.
4. Изменять только согласованные разрешённые файлы.
5. Проверить результат в WSL через CMake/CTest, не переписывая запрещённые части.
6. Предложить запись в `docs/agent_log/lab_2.md`: запрос, результат, что принято/отклонено, проверка, ошибки документации и исправления.

Студент отвечает за весь код и документацию и должен быть готов объяснить любую строку и самостоятельно вывести формулы алгоритма.
